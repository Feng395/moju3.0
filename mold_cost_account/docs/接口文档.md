## 认证接口

### 1. 用户登录

获取JWT访问令牌。

**接口**: `POST /api/login`

**请求头**:
```
Content-Type: application/json
```

**请求参数**:
```json
{
  "username": "admin",      // 必填，用户名
  "password": "123456"      // 必填，密码
}
```

**成功响应** (200):
```json
{
  "success": true,
  "message": "登录成功",
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "user_info": {
    "user_id": "a63b7863-5faf-4b00-9ec3-758495b0fb66",
    "username": "admin",
    "email": "admin@example.com",
    "real_name": "系统管理员",
    "role": "admin",
    "department": "IT部门",
    "is_active": true,
    "last_login_at": "2026-01-18T07:00:00",
    "created_at": "2024-01-01T00:00:00"
  }
}
```

**失败响应** (400/401):
```json
{
  "success": false,
  "message": "用户名或密码错误"
}
```

**示例**:
```bash
curl -X POST http://192.168.0.14:8000/api/login \
  -H "Content-Type: application/json" \
  -d '{"username":"admin","password":"123456"}'
```

### 2. Token验证

验证JWT令牌的有效性。

**接口**: `POST /api/verify-token`

**请求头**:
```
Content-Type: application/json
```

**请求参数**:
```json
{
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
}
```

**成功响应** (200):
```json
{
  "success": true,
  "message": "token有效",
  "payload": {
    "sub": "admin",
    "user_id": "a63b7863-5faf-4b00-9ec3-758495b0fb66",
    "role": "admin",
    "email": "admin@example.com",
    "real_name": "系统管理员",
    "exp": 1770522432
  }
}
```

**失败响应** (401):
```json
{
  "success": false,
  "message": "token无效或已过期"
}
```

## 工艺规则接口

所有工艺规则接口都需要在请求头中携带有效的JWT token。

**请求头**:
```
Authorization: Bearer <your_token>
Content-Type: application/json
```

### 1. 创建工艺规则

**接口**: `POST /api/process-rules`

**请求参数**:
```json
{
  "id": "R001",                      // 必填，规则ID
  "version_id": "v1.0",              // 必填，版本号
  "feature_type": "WIRE",            // 必填，特征类型（WIRE/NC/EDM等）
  "name": "线割规则1",                // 必填，规则名称
  "description": "这是一个线割规则",   // 可选，规则描述
  "priority": 10,                    // 可选，优先级（默认0）
  "is_active": true,                 // 可选，是否激活（默认true）
  "conditions": "length > 100",      // 必填，规则条件（≤255字符）
  "output_params": "speed=100"       // 必填，输出参数（≤255字符）
}
```

**成功响应** (201):
```json
{
  "success": true,
  "message": "规则创建成功",
  "data": {
    "id": "R001",
    "version_id": "v1.0",
    "feature_type": "WIRE",
    "name": "线割规则1",
    "description": "这是一个线割规则",
    "priority": 10,
    "is_active": true,
    "conditions": "length > 100",
    "output_params": "speed=100",
    "created_at": "2026-01-18T08:00:00"
  }
}
```

**失败响应** (400):
```json
{
  "success": false,
  "message": "缺少必填字段: id"
}
```

## Token自动刷新机制

所有需要认证的接口都支持Token自动刷新功能。

### 工作原理

1. 客户端在请求头中携带token
2. 服务器验证token并检查剩余有效时间
3. 如果剩余时间 < 总有效期的50%，服务器生成新token
4. 新token在响应中返回（字段名：`new_token`）
5. 客户端收到新token后，应更新本地存储的token

### 配置参数

- **总有效期**: 30000分钟（约21天）
- **刷新阈值**: 0.5 (50%)
- **刷新窗口**: 15000分钟（约10.5天）

### 响应示例（包含新token）

```json
{
  "success": true,
  "message": "操作成功（token已刷新）",
  "data": {},
  "new_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
}
```

### 客户端处理

```javascript
// JavaScript示例
const response = await fetch(url, {
    headers: {
        'Authorization': `Bearer ${token}`
    }
});

const data = await response.json();

// 检查并更新token
if (data.new_token) {
    localStorage.setItem('token', data.new_token);
    console.log('Token已自动刷新');
}
```

## 错误码说明

| HTTP状态码 | 说明 |
|-----------|------|
| 200 | 请求成功 |
| 201 | 创建成功 |
| 400 | 请求参数错误 |
| 401 | 未授权（token无效或缺失） |
| 403 | 权限不足 |
| 404 | 资源不存在 |
| 500 | 服务器内部错误 |

### 错误响应格式

```json
{
  "success": false,
  "message": "错误描述信息"
}
```

### 常见错误

| 错误信息 | 原因 | 解决方法 |
|---------|------|---------|
| 缺少Authorization头 | 请求头中没有token | 添加Authorization头 |
| Token无效或已过期 | token验证失败 | 重新登录获取新token |
| 缺少必填字段: xxx | 请求参数不完整 | 检查并补充必填字段 |
| 规则不存在 | 请求的资源不存在 | 检查资源ID是否正确 |
| 权限不足 | 用户角色权限不够 | 使用有权限的账号 |

## 通用说明

### 1. 认证方式

除登录接口外，所有接口都需要在请求头中携带JWT token：

```
Authorization: Bearer <your_token>
```

### 2. 时间格式

所有时间字段使用ISO 8601格式：

```
2026-01-18T08:00:00
```

### 3. 分页参数

支持分页的接口统一使用以下参数：

- `page`: 页码（从1开始）
- `page_size`: 每页数量（默认20）

### 4. 布尔值

布尔类型参数使用：

- `true` / `false` (JSON)
- `true` / `false` (URL查询参数)

### 5. 数值字段

价格项中的数值字段（price、work_hours等）都是VARCHAR类型，存储为字符串。

### 6. 字段长度限制

- `conditions` 和 `output_params`: 最大255字符
- 其他字段参考数据库表定义
