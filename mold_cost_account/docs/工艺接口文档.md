# 工艺规则接口文档

## 基础信息

**服务地址**: `http://192.168.0.14:8000`  
**接口前缀**: `/api/process-rules`  
**数据格式**: JSON

---

## 数据模型

### ProcessRule 对象

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| id | string(50) | 是 | 规则唯一标识，如R001 |
| version_id | string(20) | 是 | 规则版本号，如v1.0 |
| feature_type | string(20) | 是 | 特征类型：WIRE-线割, NC-数控等 |
| name | string(100) | 是 | 规则名称 |
| description | text | 否 | 规则描述 |
| priority | integer | 否 | 优先级，数值越大优先级越高（默认0） |
| is_active | boolean | 否 | 是否激活（默认true） |
| conditions | string(255) | 是 | 规则条件，字符串格式 |
| output_params | string(255) | 是 | 输出参数，字符串格式 |
| created_at | timestamp | 自动 | 创建时间 |

## 接口列表

### 1. 创建工艺规则

**接口**: `POST /api/process-rules`

**请求参数**:
```json
{
  "id": "R001",                    // 必填，规则ID
  "version_id": "v1.0",            // 必填，版本号
  "feature_type": "WIRE",          // 必填，特征类型（WIRE-线割, NC-数控等）
  "name": "线割规则1",              // 必填，规则名称
  "description": "这是一个线割规则", // 可选，规则描述
  "priority": 10,                  // 可选，优先级（默认0）
  "is_active": true,               // 可选，是否激活（默认true）
  "conditions": "length > 100",    // 必填，规则条件（≤255字符）
  "output_params": "speed=100"     // 必填，输出参数（≤255字符）
}
```

**响应示例**:
```json
{
  "success": true,
  "message": "规则创建成功",
  "data": {
    "id": "R001",
    "version_id": "v1.0",
    "feature_type": "WIRE",
    "name": "线割规则1",
    "priority": 10,
    "is_active": true,
    "conditions": "length > 100",
    "output_params": "speed=100",
    "created_at": "2024-01-13T12:00:00"
  }
}
```

### 3. 获取规则列表

**接口**: `GET /api/process-rules`

**查询参数**:
| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| page | int | 否 | 页码（默认1） |
| page_size | int | 否 | 每页数量（默认20） |
| version_id | string | 否 | 版本号筛选 |
| feature_type | string | 否 | 特征类型筛选 |
| is_active | boolean | 否 | 是否激活筛选 |
| name | string | 否 | 名称模糊搜索 |

**请求示例**:
```bash
# 获取所有规则
GET /api/process-rules

# 筛选版本v1.0的规则
GET /api/process-rules?version_id=v1.0

# 筛选WIRE类型的规则
GET /api/process-rules?feature_type=WIRE

# 名称模糊搜索
GET /api/process-rules?name=线割

# 分页查询
GET /api/process-rules?page=1&page_size=10

# 组合筛选
GET /api/process-rules?version_id=v1.0&feature_type=WIRE&is_active=true
```

**响应示例**:
```json
{
  "success": true,
  "message": "获取成功",
  "data": {
    "total": 10,
    "page": 1,
    "page_size": 20,

      {
        "id": "R001",
        "version_id": "v1.0",
        "feature_type": "WIRE",
        "name": "线割规则1",
        "description": "这是一个线割规则",
        "priority": 10,
        "is_active": true,
        "conditions": "length > 100",
        "output_params": "speed=100",
        "created_at": "2024-01-13T12:00:00"

    ]
  }
}
```

### 7. 根据版本和类型获取规则

**接口**: `GET /api/process-rules/by-version-type`

**查询参数**:
| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| version_id | string | 是 | 版本号 |
| feature_type | string | 是 | 特征类型 |
| active_only | boolean | 否 | 是否只返回激活的规则（默认true） |

**请求示例**:
```bash
# 获取v1.0版本的WIRE类型规则（只返回激活的）
GET /api/process-rules/by-version-type?version_id=v1.0&feature_type=WIRE

# 获取所有规则（包括未激活的）
GET /api/process-rules/by-version-type?version_id=v1.0&feature_type=WIRE&active_only=false
```

**响应示例**:
```json

  "data": [
    {
```

### Python示例

```python
import requests

base_url = "http://192.168.0.14:8000/api/process-rules"

# 创建规则
rule_data = {
    "id": "R001",
    "version_id": "v1.0",
    "feature_type": "WIRE",
    "name": "线割规则1",
    "description": "这是一个线割规则",
    "conditions": "length > 100",
    "output_params": "speed=100"
}
response = requests.post(base_url, json=rule_data)
print(response.json())

# 获取规则列表
response = requests.get(base_url, params={"version_id": "v1.0"})
print(response.json())

# 更新规则
update_data = {"name": "更新后的名称", "description": "更新后的描述", "priority": 20}
response = requests.put(f"{base_url}/R001", json=update_data)
print(response.json())

# 删除规则
response = requests.delete(f"{base_url}/R001")
print(response.json())
```

## 注意事项

1. **字段长度限制**
   - `conditions` 和 `output_params` 字段最大长度为255字符
   - 超过限制会返回400错误

2. **唯一性约束**
   - `id` 字段必须唯一
   - 重复的ID会导致创建失败

3. **优先级排序**
   - 规则列表按优先级降序排列
   - 相同优先级按创建时间降序排列

4. **激活状态**
   - 默认情况下，`by-version-type` 接口只返回激活的规则
   - 可通过 `active_only=false` 参数获取所有规则

5. **分页限制**
   - 默认每页20条记录
   - 建议最大每页100条记录
